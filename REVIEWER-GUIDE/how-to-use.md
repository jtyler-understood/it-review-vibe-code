# How to use this practice review

This exercise takes about 30 to 45 minutes. You don't need to run anything or install anything. You only need to read files and search them.

## The scenario

Sam Builder on the Example Team just sent IT a request. Sam used an AI tool to build an app that pulls Jira tickets and Google Calendar events, summarizes them, and posts the summary to Slack. Sam says it's "already working, so this should be quick."

Your job is to review it the way you'd review a real request.

## Steps

1. **Read the request.** Open `weekly-digest/REQUEST.md` and read it as if it just landed in your queue. Note anything that's missing, vague, or doesn't add up.
2. **Skim the project.** Open the [cheat sheet](cheat-sheet.md). Work through it section by section, searching the `weekly-digest` folder for each term. On GitHub, open a file and use your browser's find (Ctrl+F or Cmd+F), or press `t` to find a file by name. If you use GitHub's search box, add `path:weekly-digest/` to your search (for example, `xoxb- path:weekly-digest/`). Otherwise your results will include the cheat sheet and the answer key, which spoils the exercise.
3. **Fill in the worksheet.** Use the [review worksheet](review-worksheet.md) to mark each checklist item as Pass, Fail, or Can't tell, with what you found and where.
4. **Check your answers.** When you're done, open `zz-answer-key.md` in this folder and compare. It's named so it sorts last.

## Tips

- **Compare the request to the code.** What a builder says the app does and what the code actually does are often different. That gap is one of the most important things to catch.
- **Look at every file, not just the code.** Settings files, notes, and hidden files (names that start with a dot, like `.env`) often hold the biggest problems.
- **"Can't tell" is a fine answer.** If the request doesn't give you enough to decide, that's a finding too. Ask the builder.

## Using the cheat sheet on real requests

The cheat sheet isn't only for this exercise. The same search terms work on real projects, so keep it handy.
